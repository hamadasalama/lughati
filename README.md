# منصة لغتي — تقييم طالبات مادة اللغة العربية

تطبيق ويب متكامل (Full-Stack): واجهة React + TypeScript، خادم Node.js/Express + TypeScript،
قاعدة بيانات PostgreSQL حقيقية، مصادقة بجلسات آمنة وصلاحيات مفروضة في الخادم.

**النسخة المنشورة:** https://lughati.onrender.com

**إعداد وتنفيذ: أ. مها الحمادي**
مديرة المدرسة: أ. بدور الجارد

---

## المتطلبات
- Node.js 20.19 أو أحدث
- PostgreSQL 14 أو أحدث يعمل محلياً

## التشغيل للتطوير (كل الأوامر من جذر المشروع)

1) **تثبيت تبعيات المشروعين معاً** (npm workspaces — مرة واحدة فقط من الجذر):

       npm install

2) **إنشاء ملف البيئة**: انسخي `.env.example` إلى `.env` وعدّلي:
   - `DATABASE_URL`: بيانات اتصالك بـ PostgreSQL.
     تنبيه: كلمة مرور تحتوي رموزاً مثل `@` أو `:` تفسد الرابط — استخدمي حروفاً وأرقاماً فقط.
   - `JWT_SECRET`: أي نص عشوائي طويل.

3) **إنشاء قاعدة البيانات والجداول والبيانات الأساسية:**

       npm run db:create
       npm run migrate
       npm run seed

   يُنشئ الـ seed حساب المعلمة الأول:
   - اسم المستخدم: `maha`
   - كلمة المرور: `lughati1234`

   **غيّري كلمة المرور فوراً من «الإعدادات» بعد أول دخول.**

4) **تشغيل الخادم** (نافذة أوامر):

       npm run dev:server

   تأكدي من: http://localhost:4000/api/health → `{"status":"ok","db":"ok",...}`

5) **تشغيل الواجهة** (نافذة أوامر ثانية):

       npm run dev:web

   ثم افتحي http://localhost:5173

## إدخال الطالبات
من شاشة «الطالبات» ← «استيراد الطالبات»:

**الطريقة الأولى: ملف Excel / CSV** (مع حسابات الدخول)

| العمود | إلزامي | ملاحظات |
|---|---|---|
| الرمز | لا | هوية ثابتة للطالبة، ويُستخدم اسم مستخدم افتراضياً |
| الاسم | نعم | اسم الطالبة |
| الصف / الشعبة | لا | الافتراضي: الرابع / أ |
| اسم المستخدم | لا | يُستخدم للدخول، وإلا يُستخدم الرمز |
| كلمة المرور | للحساب الجديد | 8 أحرف على الأقل وتحتوي حرفاً ورقماً |
| ملاحظات | لا | نص حر |

- تُقبل الصيغ `.xlsx` و`.csv` (حتى 10MB و1000 صف)، مع دعم الترويسات العربية والإنجليزية.
- زر **تنزيل قالب CSV** ينتج ملفاً جاهزاً بالأعمدة الصحيحة وبترميز UTF-8 مع BOM ليُفتح في Excel بلا مشاكل عربية.
- إعادة استيراد الرمز نفسه **تحدّث** بيانات الطالبة وحسابها، وتغيير كلمة المرور يُبطل جلسات الطالبة القديمة.
- إن وُجد الرمز في الملف تُطابَق الطالبة به، وإلا تُطابَق بالاسم+الصف+الشعبة؛ وصفوف الملف المكررة تُرفض.
- كلمة مرور ضعيفة أو اسم مستخدم محجوز يرفض الصف فقط (لا يُسقط بقية الملف)، وتظهر تفاصيل الأخطاء بأرقام الصفوف.
- الملف بلا ترويسة يُقرأ بالترتيب: `الاسم، الصف، الشعبة، الرمز، اسم المستخدم، كلمة المرور، ملاحظات`.

**الطريقة الثانية: لصق أسماء** — سطر لكل طالبة بالصيغة `الاسم، الصف، الشعبة` (الصف والشعبة اختياريان). تُتجاهل المكررات تلقائياً.
كذلك يمكن الاستيراد من `database/students.csv` بالصيغة القديمة. لا توجد أسماء جاهزة في القاعدة — الإدخال منك فقط.

## تخصيص الهوية والمظهر (من «الإعدادات»)
- **نصوص الواجهة**: عنوان المنصة ووصفها، اسم المدرسة ووصفها في صفحة الدخول، الاقتباسات الثلاثة، واسم معدّة المنصة ومسمىها الوظيفي — كلها قابلة لإعادة الكتابة فوراً.
- **الألوان والخط**: اللون الأساسي ولون القائمة الجانبية ولون العناوين، ونوع الخط وحجم النص الأساسي وحجم العناوين وتباعد الأسطر.
- **الخلفية**: لون ثابت، أو تدرّج لوني (لونان + زاوية)، أو صورة مرفوعة مع نسبة تعتيم وتحكم في ثباتها عند التمرير.
- يُعرض **معاينة حيّة** داخل صفحة الإعدادات قبل الحفظ، وتُطبَّق التغييرات على كل الصفحات بما فيها صفحة الدخول.
- الصورة القديمة للخلفية تُحذف من القرص تلقائياً عند استبدالها أو إزالتها، ويمكن استعادة المظهر الافتراضي بضغطة.
- شعار المدرسة المرفوع من الإعدادات يظهر في القائمة الجانبية وصفحة الدخول، وإلا يُستخدم الشعار الافتراضي `/logo.png`.
- **اسم المعلمة الظاهر**: يُعدَّل من «بيانات المدرسة» ويظهر في الترحيب والقائمة الجانبية بدل اسم الدخول `maha`.
- صفحة الدخول تحتاج الهوية قبل المصادقة، لذلك `GET /api/settings/public` و`GET /api/files/public/:id` عامّان (للشعار والخلفية فقط).

## لوحة التحكم
صفحة «لوحة التحكم» هي نقطة البداية للمعلمة والإدارة: مؤشرات سريعة (عدد الطالبات، التقييمات، متوسط الأداء، المتفوقات، نسبة الحضور)،
نجمة الأسبوع، طالبات يحتجن متابعة، أحدث الاختبارات، توزيع الطالبات على الصفوف، واختصارات لكل أقسام المنصة.

## الاختبارات الآلية (67 اختباراً ضد PostgreSQL حقيقي)

    npm run db:create -- test
    npm test

تغطي: تسجيل الدخول والجلسات وإبطالها عند الخروج، فرض الصلاحيات في الخادم،
خصوصية ملفات الطالبات (بما فيها أوراق العمل المسندة لطالبات بعينهن)،
رفض الملفات المزيفة المحتوى، ترويسات الأمان، دور الإدارة، التقييم التراكمي
(تقييمان بنفس اليوم)، منع درجات الغائبات، رصد النتائج وحذف الدرجة الفارغة
ورفض طالبة من صف آخر، الاستيراد الجماعي ومنع تكرار الطالبات،
حساب الأسبوع (يبدأ الأحد)، وإبطال الجلسة عند تغيير كلمة المرور،
وقفل محاولات الدخول بعد 5 محاولات (مخزَّن في PostgreSQL ليعمل مع أكثر من نسخة خادم)،
وشكل صفحة سجل التدقيق (`items`/`total`/`limit`/`offset`) وحصرها على الإدارة،
ودورة حياة حساب الطالبة (إنشاء ← دخول ← إيقاف يقطع الجلسة فوراً ← تفعيل يعيد الدخول)،
والاسم الظاهر للمعلمة، والإعدادات العامة للمظهر، وتنقية نصوص/ألوان الثيم ومنع حقن الصور والألوان،
ورفع خلفية صالحة ورفض غير الصور، وحذف الصورة القديمة عند الاستبدال أو الإزالة،
ووصول صفحة الدخول للشعار/الخلفية دون مصادقة مع حجب بقية الملفات،
واستيراد الطالبات من Excel/CSV مع إنشاء الحسابات وتحديث كلمات المرور،
ورفض كلمة المرور الضعيفة/المفقودة واسم المستخدم المحجوز دون إسقاط بقية الملف،
وقراءة الملفات بترويسة عربية أو بلا ترويسة (ترتيب الأعمدة الافتراضي).

## التشغيل الإنتاجي

> للنشر المجاني خطوة بخطوة على Render + Neon راجعي **[DEPLOY.md](DEPLOY.md)**. يوجد ملف `render.yaml` جاهز للـ Blueprint.

    npm run build      # يبني الواجهة داخل frontend/dist
    npm start          # يقدم الواجهة والـ API معاً من نفس المنفذ

ملاحظات:
- في `.env` ضعي `NODE_ENV=production` و`JWT_SECRET` قوياً و`CORS_ORIGIN` بنطاقك.
- عند التشغيل خلف وكيل عكسي (Nginx/IIS) اضبطي `TRUST_PROXY=1` حتى يُقرأ IP الحقيقي في حد محاولات الدخول.
- في الإنتاج تُرسل كوكي الجلسة بعلامة `Secure` — تحتاجين HTTPS (عبر IIS أو Nginx كوكيل عكسي).
- يُستحسن تفعيل فحص ClamAV: ثبّتي `clamav` ثم `CLAMAV_ENABLED=true`. عند التفعيل يُرفض أي ملف إذا تعذّر الفحص (fail-closed)، واضبطي `CLAMAV_BIN` و`CLAMAV_TIMEOUT_MS` حسب الخادم.
- `npm run migrate` يطبّق كل الترحيلات بالترتيب على قاعدة البيانات (بما فيها `003` الخاص بفهارس الأداء وجدول `login_throttle`، و`004` الذي يفرض تفرّد اسم المستخدم بغض النظر عن حالة الأحرف، و`005` الذي يحفظ نسخة من المرفقات داخل قاعدة البيانات لتبقى على الاستضافات ذات القرص المؤقت).
- `npm start` يطبّق الترحيلات الناقصة تلقائياً قبل فتح المنفذ (بقفل يمنع تعارض النسخ)، ويتوقف برسالة واضحة إذا فشل الترحيل — لا يعمل الخادم على مخطط قديم.
- صفحة «الإدارة» تظهر في القائمة لدور `admin` فقط: إدارة حسابات المعلمات/الإدارة وسجل التدقيق مع بحث وصفحات. لا يمكن للإدارة إيقاف أو حذف حسابها الحالي.
- النسخ الاحتياطي الدوري: `pg_dump -U postgres lughati > backup.sql`
- لا ترفعي `.env` ولا مجلد `uploads/` إلى أي مكان عام.

## أمان مدمج
- كلمات المرور مجزأة bcrypt داخل الخادم فقط — لا شيء حساس في كود الواجهة.
- الجلسة JWT داخل كوكي httpOnly (8 ساعات) + `token_version` لإبطال فوري عند تغيير كلمة المرور أو تسجيل الخروج.
- دور كل مستخدم يُقرأ من قاعدة البيانات مع **كل طلب** — الصلاحيات ليست إخفاء واجهة.
- الطالبة ترى بياناتها فقط؛ ملفاتها لا تُفتح بتغيير الرابط (404 دون كشف).
- الملفات تمر عبر `/api/files/:id` فقط، ويُفحص محتواها الفعلي (بايتات سحرية) لا نوعها المُعلن فقط.
- ترويسات أمان عبر Helmet (nosniff, frameguard, referrer-policy) + HSTS وCSP صارمة في الإنتاج + ضغط الاستجابات.
- حد محاولات دخول لكل اسم مستخدم ولكل IP، ومقارنة bcrypt ثابتة الزمن نسبياً.
- سياسة كلمة مرور: 8 خانات على الأقل، حرف ورقم، وبحد أقصى 72 بايت (حد bcrypt)، مطبقة في الخادم والواجهة.
- سجل تدقيق (audit_logs) للعمليات الحساسة يعرضه دور «الإدارة»، وفشل التسجيل لا يُسقط العملية.
- التقييم تراكمي؛ لا درجات لأي طالبة غير حاضرة (قيد في القاعدة + فحص بالخادم).

## الضغط إلى ZIP
كليك يمين على مجلد `lughati` ← «ضغط إلى ملف ZIP».

ولا تضمّني `.env` عند المشاركة مع أي جهة خارجية.
